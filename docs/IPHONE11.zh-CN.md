# iPhone 11：A13 实验性支持

[English](IPHONE11.md) | **简体中文**

`mtl3-fallback` 分支增加了 **iPhone 11（A13，4 GB）的实验性支持，实测系统为 iOS 26.3**。这是本分支的测试结果，不代表上游 main 已改变设备支持承诺。其他 A13 机型、A12 设备以及其他 4 GB 设备尚未由本次工作验证。

## 改了什么

| 部分 | 实现 |
|---|---|
| 图形 | Metal 4 队列不可用时，使用经典 Metal 队列、命令缓冲与编码器。顶点 / 索引缓冲按对象和偏移绑定；间接参数缓冲通过 `MTLArgumentEncoder` 编码，并声明资源用途。 |
| 贴图 | 补充经典上传、亮度 LUT 与 ASTC 拷贝路径，仍需老机型补充包。跳过仅支持 Metal 4 的泛光 / 帧外推优化，使用已有回退路径。 |
| 内存 | 保留完整内存池地址映射，首次使用时才登记驻留，等 GPU 完成后退役资源。这项优化上游 main 也已实现，本分支将其整合进 A13 路径。实验性的局部池映射默认关闭。 |
| 默认配置 | 对不超过 4 GB 且不具备 Apple7 GPU 家族的设备，启用低内存配置：输出宽度上限 1280、3D 比例 0.5、30 FPS、Granny 预解码缓存 32 MiB。保留环境变量显式覆盖能力。 |
| 触摸 | 低内存模式下补充原生“创建”“标准 / 专家”“开始游戏”按钮。开始操作由游戏线程发送原版 `MainMenuHD:Play` 消息。 |
| 测试 | 增加经典内存池复制、间接指针、边界与首次驻留检查，保留上游 NVN 和帧节奏测试。 |

输出上限保留宽高比；本次 iPhone 11 实测输出为 1280×592，3D 渲染约为 640×296。这些设置不能减少所有类别的内存占用。

## 构建与运行

按仓库准备说明，使用本分支普通的 iOS 26 构建路径。自备游戏文件与[老机型补充包](LEGACY_DEVICES.zh-CN.md)，本分支不提供这些资源。A13 运行时回退会自动选择。独立的 `DM_IOS_M3=1` 构建用于老系统，不是本次 iPhone 11 验证使用的配置。

着色器库须由检出的源码与工具链生成。生成的 `dmsh_chain.h` 版本必须和打包的 `msl/b-<版本>` 目录一致，不要复制其他开发者的本地着色器指纹或签名配置。发布前仍需独立验证干净检出后的完整资源生成与构建流程。

## 验证范围与限制

- 合入 main 前，测试者确认可以创建角色、读取已有存档、进入其他区域，并进行了估计约十分钟的短时游玩。其中一次拉取的日志记录约五分钟前台运行。
- 合入 main 后，已能读取存档进入游戏。随后一次静置观察到约 160 秒，约 30 FPS、1771 MiB footprint，该观察窗口内未见持续增长。
- iOS Release 编译通过；默认与编译期旧 API 的 NVN 测试各通过 75 项，帧节奏通过 23 项；经典内存池测试在 M4 Max 上启用 Metal API Validation 后通过。桌面测试不能证明 A13 的场景兼容性。
- GPU 上屏超时尚未解决：合并后一次会话出现连续错误 / 提交被忽略，后一次会话进局超时一次后恢复。温控达到 2（严重），切换区域时贴图上传仍可能造成停顿。

以上不是稳定性或性能保证。长时间游玩、后续章节、更高难度与反复切图仍需验证。测试前请备份存档。早期调查见[内存实测记录](IPHONE11_MEMORY_DEBUG.zh-CN.md)与[可行性报告](MTL3_FALLBACK_FEASIBILITY.zh-CN.md)；其中历史假设不应作为当前实现指南。

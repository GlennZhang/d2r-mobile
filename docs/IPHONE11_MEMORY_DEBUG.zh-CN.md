# iPhone 11 内存问题实测记录

> 历史调查记录：包含当时的假设、失败实验和待验证事项。当前实现、实测进展与已知问题以 [iPhone 11 实验性支持](IPHONE11.zh-CN.md)为准；尤其不要按早期建议移除经典路径驻留集。

2026-10-15，iPhone12,1 / A13 / iOS 26.3。

## 已确认

- 输出 1280×592、3D 比例 0.5、30 FPS 已生效。
- 禁用 PSO 预热和 Granny 预解码后，40 秒日志仍约 1616 MiB footprint；对应系统 Jetsam 报告 `JetsamEvent-2026-10-15-011348.ips`，PID 855，原因 `vm-pageshortage`，1615 MiB。此优化不足以解决退出。
- GPU `currentAllocatedSize` 约 2008 MiB，并不等同于进程 footprint，不能把两者相加。
- 游戏创建 7 个内存池：512、10、400、1、710、2、40 MiB，共 1675 MiB。其中 512 MiB 池 flags=0xa1，710 MiB 池 flags=0x21。所有池均有 GPU 访问标志。
- 之前对所有池使用小块映射的实验触发真实游戏 GPU 地址错误，默认停用。移除经典队列的驻留集也曾失败，已经恢复。

## 当前默认优化：完整映射、按需驻留

移植 main 的内存池按需驻留：创建池时保留完整 Metal 缓冲和 GPU 地址映射，首次实际访问时才加入驻留集并立即提交。销毁后等 GPU 完成再释放驻留引用。未使用的 512 MiB 池不会被主动加入驻留集。

Release 构建通过并已安装到 iPhone 11。M4 Max 的 Metal API Validation 测试通过，包含未使用池不驻留、首次访问提交驻留，以及原有复制和间接指针检查。真机启动日志确认 400、710、40、2、1 MiB 池按需驻留，尚无 512 MiB 池首次使用记录。

首次采样 34 秒 footprint 约 1632 MiB，62 秒约 1840 MiB；因此暂不能宣称降低了进程 footprint。系统 wired 内存与 footprint 不是同一指标，是否缓解 Jetsam 仍需持续运行和进入游戏验证。

同次运行 124 秒时进程仍存活，footprint 1844 MiB、距进程上限约 253 MiB；已采集到 1500 帧的日志中没有 GPU 地址错误或驻留缺失。此结果仅证明该次运行超过两分钟，不能代替进入游戏验证。

## 保留的诊断实验（默认关闭）

`DM_CLASSIC_LARGE_POOL_RANGES=1` 仅让经典 Metal 下不小于 512 MiB 的池按访问范围建缓冲；较小的着色器、顶点等池保留完整映射。无此环境变量时保留原有完整映射。

构建通过。`t_classic_pool` 在 M4 Max 上启用 Metal API Validation 后验证通过：跨窗口复制、参数表间接指针读取、选择性映射小池完整/大池局部，以及越界和销毁后拒绝查找。

这些单独测试不能证明游戏兼容，更不能证明 A13 节省了 footprint。此范围映射开关尚未完成 A13 验证，当前真机测试不启用它。

## 下一步验证

1. 使用默认按需驻留版本记录内存及完整 boot 日志，检查 GPU 地址错误、超时、驻留缺失和上传错误。
2. 对照 Jetsam 系统报告确认是否仍由系统内存压力杀进程。
3. 验证创建角色、选择难度、进入游戏的完整流程。

创建/模式选择的 UIKit 补充按钮已在当前包中，但完整创建角色与进入游戏流程仍需真机验证。当前不能宣称闪退已修复。
